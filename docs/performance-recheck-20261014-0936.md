## 计时风险

`web/src/utils/performanceDiagnostics.js` 用 `node_tree_render_start` 开始计时、`render_complete` 结束计时，但 `Render.js` 中视图变化局部渲染会发 `node_tree_render_start`/`node_tree_render_end` 而不发 `render_complete`。跨路径配对可能把等待时间混入下一次完整渲染，是 79.9 秒异常的候选解释；尚未通过该窗口调用栈确认。该 render 指标暂不能作为纯 CPU 时间。长任务测量与 ACK 端到端延迟仍支持有真实卡顿。

## 判断与后续顺序

现有数据足以确认客户端仍有明显卡顿，MCP 全树写入路径也比浏览器 direct 路径重。尚不能证明 MCP 是全部多人卡顿的唯一原因。优先校正渲染测量配对，确认展开按钮异常修复的部署/缓存情况，再查大批节点展开的布局/SVG工作和恢复期间的请求调度。MCP 需要用同一操作、同一房间做隔离对比，再决定写入路径优化；不要直接启用事件桥或改协议。
