## WB 报告哪些成立

1. `mindDoc.toOutline` 截断提示确实建议 `get_map format=nodes with uid`，而 MCP schema 仅接受 outline/full，这是确定的错误提示。
2. full 只有节点数预算，没有字节预算；长备注等仍可能放大响应。`raise max_nodes` 提示不利于控制上下文。报告的 218KB 是其特定样本，不能把字节除以四当作准确 token 数。
3. 诊断工具没有 summaryOnly；默认包含原始事件。本次已回升到约 266KB，支持输出预算问题。环形队列上限 3000，具体大小取决于事件内容，不保证固定时间后必达 574KB。

这三个 MCP 输出问题本轮仅核对，未混入此前授权的三个浏览器加载修复。

## WB 报告哪些不能作为根因结论

- eventBridge duplicateNotifications 是被去重的后台唤醒数，不等于客户端收到同等比例的重复广播。
- eventBridge=false 与 mcpDirectConfigured=false 不等于关闭浏览器实时协作；代码保留 Socket.IO 直接广播，本次也有远端接收样本。MCP 写入路径需要独立验证。
- revision 高、节点多、备注少不能认定房间为垃圾或授权删图/拆图。
- monitorEventLoopDelay 使用 20ms 分辨率，正常 P50 接近 20ms；它不是每个 HTTP 请求被阻塞的时间。
- 两轮负载、uptime、客户端行为不一致，不能单凭延迟下降证明“关闭事件桥”是唯一原因。当前样本的浏览器排队/渲染明显高于服务端子树耗时，更应继续验证客户端开销。
