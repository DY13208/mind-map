# CPD 检查按钮

## 范围与使用

选中业务节点，点击「检查」，读取对应的完整链路、祖先、相关 C/P/D、备注和附件正文。报告显示阻断项、缺项、提示、来源、候选流程及检查历史。多个可能对应关系需要用户确认后继续检查；只读用户可以查看报告。

选中 D 时，只检查该 D 子树、最近的相关 P 和相关 C 条目；祖先只作上下文，不展开其其他业务分支。选中 P 时检查该 P 的有界任务分支；选中 C 或容器且包含多个 P 时先确认一条。面板显示实际范围和节点数。

本次只实现检查按钮。检查仅保存报告、来源和用户选择，不修改脑图、不导入资料、不派任务、不写执行台账。已有运行入口保持原样。

## 规则与来源

- 规则沿用检查总表 CK 编号。程序核验结构、明确字段、材料引用和版本，不设置语义分析或模型辅助判断阶段。无法从明确关系与字段确认的事项列出原文及需要核对的内容，不自动判定通过。
- 检索顺序为本链路 → 当前图资料及房间绑定知识库 → Wiki。链路材料已足够时不继续检索。Wiki 通过编译图谱的只读查询接口检索当前有效材料。
- 找到外部材料仅记录为候选；当前图仍缺字段或引用时保持待补齐。
- 用户确认流程后，读取完整来源作为参考，比较明确字段和材料差异，不对文字含义作模型判断。对照项使用辅助标识 `FLOW-COMPARE`，不改变原文 CK 编号含义；来源或链路未变化时可复用流程选择。
- 整图评级、全图覆盖不用于单链路结论；十三个 SOP 卡字段只检查实际 SOP 卡；执行与完成规则不在静态检查中判定。
- 检查不读取 OpenClaw、DeepSeek 等模型配置，不调用模型或助理会话。知识检索只调用读取接口。
- 附件未解析、无权限、来源不可用、读取超限不能视为通过。单份附件读取预算为 20 万字符，链路附件总预算为 40 万字符，超限会明确标记不完整。

## 接口与数据库

房间接口前缀 `/api/files/:room/cpd-checks`：

| 请求 | 用途 |
| --- | --- |
| `POST /` | 创建检查，输入 `nodeUid`、`requestId` |
| `GET /?nodeUid=...` | 查询检查历史 |
| `GET /:id` | 读取报告并核验是否过期 |
| `POST /:id/confirm` | 用户确认 `candidateId` 后继续检查 |

读取需要房间查看权限，创建和确认需要编辑权限。链路、规则或已确认来源版本变化后需复检。

新增独立 `check_runs` 表，记录链路、地图版本、链路指纹、规则版本、来源版本、候选选择、逐项结果及操作者。迁移文件为 `simple-mind-map/migrations/008_check_runs_v1.sql`，服务启动也会幂等初始化；原有数据库字段不变。

## 验证与运行

检查仅依赖程序规则与已接入的只读资料来源，不要求模型服务或 API 密钥。规则版本更新后旧报告读取时标记过期，需重新检查；旧历史记录保留。

### Wiki 查询与来源展示

Docker 内部默认使用 `http://wiki-graph:3848`，可通过 `CPD_WIKI_API_URL` 设置服务地址；使用应用网关时地址须包含 `/wiki-compiler`。调用 `POST /api/search` 查询有效编译主题的小节；同一主题命中多个小节时合并为一个文档候选，减少重复全文读取，不同主题仍分别列为候选、由用户确认。命中后读取主题完整正文供参考，读取前后都复核检索命中与小节正文 hash：小节不再出现在当前检索结果、正文或版本变化、主题不是 active、slug 不符、超限或字段类型非法都不会当作完整来源。`GET /api/topic` 返回的 heading 带 `[coverage:...]` 标记、search 的 section 不带，匹配时归一化，报告正文保留原始 heading。不会调用 Wiki 写入、编译或模型接口。来源正文摘要参与新鲜度检查，编译日期相同但正文改变也要求复检。

Wiki 服务读取 `WIKI_COMPILE_DIR` 对应目录，默认 `data/wiki-compiler/wiki`。目录必须包含实际编译产物 `INDEX.md`、`.compile-state.json` 和主题 Markdown；空目录时查询返回无结果。启动已有服务：`docker compose up -d wiki-graph`。

材料来源保留真实名称、节点祖先路径、文件名、Wiki 主题/小节和原始资料路径：无显式路径但有真实节点 UID 时，用链路祖先路径补齐（不伪造路径）。报告按来源身份（附件 ID、节点 UID、canonical/openwiki 路径、Wiki 主题+小节等）加版本和正文 hash 去重；同一 Wiki 主题被不同检索词命中只保留一条，`sourceRef.query` 完整保留用于有效性复核。检索状态单独按资料范围汇总，不再作为无路径的材料逐条显示。普通材料完整读取后一律保留真实来源供查看；材料中的频率、输入源、产物等明确标签只生成待核对候选，不把图中缺失字段判为通过，责任人和项目阈值不取自通用材料。

CK-32 按节点汇总缺项（缺哪几项、每项对应的原规则和字段），去掉逐条重复的问题原文与“责任人待项目补充”占位；具体字段缺失仍保留在原检查规则中。CK-30/33/34 根据实际检索范围与来源状态输出：无权限、未接入、解析失败、读取不完整等如实提示，不再固定显示“Wiki 暂未接入”，也不把失败解释为资料不存在。

本次来源展示与 Wiki 接入只扩展报告 JSON，不新增数据库字段，沿用迁移 008 和幂等初始化。规则版本已提升为 `cpd-check-v4-source-2026-09-29`，旧版本报告读取时标记过期并要求重新检查，历史记录保留。

检查项显示中文规则名称及原文 CK 编号，编号沿用《CPD专家_检查逻辑总表》，不是运行时生成的顺序号。关联节点显示业务名称，不展示节点 UID，也不提供定位节点操作。报告不再生成 `semanticService` 或模型鉴权诊断。本次取消模型阶段不新增数据库字段，不更改补齐和执行按钮。

数据库迁移和附件读取 SQL 在 PostgreSQL 临时 schema 内测试，结束回滚，不向业务脑图写测试数据。前端构建使用独立目录，不覆盖已有发布产物。代码生效需重新构建应用并启动更新后的服务。

## v5 准确性与人工核对（2026-09-29）

本轮只扩展检查报告 JSONB，不新增数据库列或修改运行、补齐入口。旧报告保留，规则版本升级后需重新检查。

- 逐项依据使用 `evidenceEntries`，区分节点正文、备注、明确字段、附件；引用必须存在于原文。系统结论与原文引用分别显示，材料未读全标为尚未核验。
- 问题采用互斥分类：结构问题、缺少信息、待核对、来源异常、提示；是否阻断独立统计。CK-32 仅汇总，不重复计数。
- 检查面板固定打开时的检查对象。问题与依据、参考资料、历史分别展示，时间显示北京时间；不提供定位节点操作或节点 UID 展示。
- 完整原文的 CK-10/27/28 及满足条件的闭环、进度分支、材料用途项可提交人工核对。必须核对全部所需依据并填写说明；缺字段、结构缺陷、不可读材料不能人工确认通过。
- 核对保存操作者、时间、原状态、依据摘要、链路指纹和规则版本。相同且仍可访问的依据可复用；链路或正文变化后失效。撤回保留审计记录。
- 检查面板固定使用正式检查，不提供模式选择。当前 `local-verify` Wiki 来源是演示资料，正式检查排除；历史演示报告仍明确标记，不能产生正式通过记录。未标注资料显示来源性质未标注。Wiki 阈值和责任角色是参考内容，不能自动成为项目值。

新增兼容接口（前缀 `/api/files/:room/cpd-checks`）：

| 请求 | 输入与用途 |
| --- | --- |
| `POST /` | 面板固定发送 `mode: business`；接口保留旧 `demo` 参数兼容 |
| `POST /:id/reviews` | `requestId`、`expectedRevision`、`findingKey`、`decision`（`confirm/reject/revoke`）、`reason`、`evidenceIds` |
| `GET /:id/sources/:sourceId` | 只读取报告登记来源，返回完整性、来源性质、变化状态和预算内正文 |
| `POST /:id/sources/:sourceId/retry` | `requestId`、`expectedRevision`；重新读取并重算检查，不改脑图 |

来源查看遵循房间查看权限；核对、重读遵循编辑权限。修订号冲突返回 409；重复请求不重复保存。服务使用事务和修订号防止覆盖，仍沿用迁移 008 的幂等初始化。
