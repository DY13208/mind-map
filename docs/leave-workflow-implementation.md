## 使用闭环

1. 用户在自己的业务节点写“我要请假”等明确意图，完成编辑后直接生成资料子节点和填写检查节点，不自动打开填写弹窗；MCP使用个人令牌调用leave_request(action=prepare)，定向读取制度、必要条件、审批步骤和人员配置，不读整张图。
2. 在申请节点下生成“申请资料”字段骨架，用户或获授权AI只在“字段 → 值”子节点填写，也支持“字段：值”。提交摘要只读，不存在第二套申请填写入口。首次读入只有明确给出的字段，不猜日期、身份、余额。正式申请人取认证身份。
3. 规则校验计算时长，提示缺项、未配置人员和需要人工核验的事项。AI补全/分析只给建议，不能决定通过。
4. 用户确认后提交，固定材料、制度要点和路由版本。按脑图部门负责人→SSC顺序生成正式待办，使用站内持久消息+现有SSE实时刷新。缺少审核人/抄送配置明确提示待配置，不根据名字猜人、不跳过步骤。
5. 当前指定审核人在同一审批面板读取来源要点、程序核验和AI分析，写实际判断依据、核验必须人工确认的事项后通过/退回/拒绝。MCP/服务身份不能代替人工点击审批。
6. 最后一步通过后通知申请人和配置的抄送对象，申请节点下更新服务端生成的概括状态；抄送不计入审批步骤。历史保留，修改节点文字不改变后台决定。

## 数据和配置

- 制度规则与人员映射来自脑图。增加“审批配置”分支，由有权维护制度的人填写“角色 → 账号：实际成员ID”，部门负责人可按“部门：部门ID → 账号：实际成员ID”配置；抄送同样明确登记。UI显示待配置说明，后端解析须匹配真实同企业成员。
- 申请字段：请假类型、开始时间、结束时间、工作替补人、请假事由、附件，外加程序计算的时长。附件仅对需要证明的类型提出要求，病假允许当月补证的规则保持人工核验。
- 时段按公司提供的工作日9:00–12:00、13:30–18:30求交集，每日8小时；时区固定Asia/Shanghai。周末和明确登记的非工作日不计，补班日支持覆盖；法定假期/调休表未配置时提示核验，不声称已接入官方考勤。
- 已确认修订：加入病假类型；恰好3天按3天及以上材料标准。其他制度文字不自动重写，不执行工资或纪律处罚。
- 年假/调休余额、司龄、试用期累计和证明真实性缺少可信业务数据时列为人工核验，不把员工自填值当作系统证明。
- 正式申请、版本、步骤、决定、AI建议和通知独立落库，脑图为可见资料/入口与状态摘要。申请正文与证明在选定脑图的现有权限范围内可见，应使用受限个人申请图；审批人只通过申请授权访问固定材料，不额外授予整图权限。

## 关键保障

服务端校验当前用户、企业、待办归属、申请版本和制度指纹。决定与下一待办/通知同事务提交，重复点击或两窗口不能重复推进。退回重提生成新轮次，从第一步重审并保留旧意见；拒绝结束当前轮次；未完成可撤回。申请内容变化不沿用旧通过。

AI分析记录绑定材料版本、步骤及来源，标为建议。没有配置AI服务时仍可用程序核验和人工审核，不把无数据或AI失败显示为已通过。

状态投影独立重试，节点已删除或服务短暂故障不会丢失正式审批结果；审批历史不随脑图入口删除而级联删除。只有真正提交/流转发送通知，编辑草稿不通知所有审核人。附件引用只接受当前申请绑定且提交者有权读取的资料；消息摘要不包含请假原因和证明正文。

## 上线准备与操作

1. 部署本分支的协作服务、MCP服务和前端；启动时自动创建独立审批表。此功能不接吉客云、金蝶，不改其单据。
2. 所有使用者须有企业成员登录身份，并能查看制度脑图、编辑自己的申请脑图。审核人通过独立申请授权看本次材料，无须获准访问申请人的整个脑图。
3. 在“请假 → 审批配置”填写部门负责人、SSC及抄送角色的真实成员ID。需要按部门区分负责人时，使用“部门：ID → 账号：user_id”。选中请假制度或角色配置节点，打开“配置请假流程”，可查询成员ID。管理员核对后发布；未配置不发送真实待办。
4. 在脑图登记节假日和补班日：`非工作日：2026-xx-xx`、`补班日：2026-xx-xx`；核实完整后登记“节假日日历已配置”。未登记完整仍显示人工核验提醒，不假称已对接考勤。
5. MCP必须使用个人令牌。新工具 `leave_request` 提供prepare/save/import/submit/status/analysis/members；不会提供代批入口。save兼容映射到节点import核对，不能绕过节点写独立字段；submit须带import/status返回的validation.nodeInputHash并明确确认。先读取当前工具清单，客户端会话需重新连接才能发现新工具。
6. 用户在个人节点写“我要请假”，完成编辑后原地生成“申请资料→字段→待填写”，双击值节点填写；或让连接了个人MCP的AI prepare并写入这些节点后import。字段子节点支持 `申请资料 → 开始时间 → 2026-10-22T09:00`，替补人填写 `账号：真实user_id`；附件上传到本申请“附件”节点或其子节点，程序读取真实attachmentId并验证同房间、节点归属与ready状态，不接受任意文本附件ID。AI不会因用户仅编辑一句话便后台发单。
7. 审核人进入“消息中心 → 业务审批 → 待我审批”，逐项核验适用性并写本次依据，再决定通过/退回/拒绝。最终状态写回子节点，记录在“我已审批/我发起的”中持续保留。
8. AI辅助分析复用已配置的OpenClaw HTTP文本流，显式禁用工具调用，不经带工具的Gateway。须在实际部署环境验证可用；不可用时显示提示并允许人工办理。余额、累计假期、司龄与证明真实性保留为人工核验。

## 节点唯一填写与确认的一致性

- 共享解析器支持“字段 → 值”和“字段：值”，忽略待填写占位；不同值重复登记会拦截，不按最后一个值静默覆盖。替补人只允许同企业精确账号或唯一准确姓名，同名必须指定成员ID。
- 编辑器对当前申请的字段变化做防抖校验，状态投影变化不重复导入。节点尚未同步时明确等待，不把本地旧快照当已提交材料。
- 核对页是只读摘要，可回到原节点继续填写。提交再次读取权威节点并比对已核对指纹；变更会要求重新核对，不能提交未看过的新材料。
- 已提交后展示不可变快照；草稿节点修改不影响当前审批。必须退回/撤回后重新登记和提交。
