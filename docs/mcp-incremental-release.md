# MCP 修复交付与发布步骤

分支：`codex/mcp-incremental-sync`；基准：`0160b5a7`。本轮停在发布前，未操作生产数据库、服务或业务房间。

## 已实现

- 旧 `nodes` 与 Direct `rows` 删除逆操作共用恢复转换，保留墓碑、父子顺序和操作者校验。
- HTTP/Socket 从在线及归档日志连续分页；真实版本缺口返回 `RESNAPSHOT_REQUIRED`。客户端只在恢复成功后推进水位，处理 ACK 先到和 join 多页同步。
- 事件桥从持久日志补齐并发送 `op:event`，总线消息只唤醒。活跃房间每秒一次批量核对版本，无客户端的房间不轮询；不支持增量回放的事件要求权威快照。
- MCP 轻量 meta，明确 UID/root 的普通新增、text/note 更新及删除使用 Direct；其他调用保留原路径。
- 可选 UUID `operation_id`、保留范围内的在线/归档幂等、有限临时错误重试，以及房间/实例写入队列。

队列：每房间1、每实例4个在途；等待数100/1000；等待30秒上限；等待 payload 估算上限64MiB。浏览器提交不进入此队列。新增核对任务运行于现有服务，无新增生产常驻服务。

## 必要验证

- 恢复兼容：7项单测，5项隔离 PostgreSQL HTTP/Socket 集成通过。
- 事件桥：11项针对性用例通过；隔离 Redis/PostgreSQL 双应用 Socket 回归通过，两端各收到一次带服务端 UID/position 的事件。
- MCP：12项有效单测通过，另有4项PG/API测试占位未执行；Direct PG 新增/更新、归档后相同 ID 重试和不同摘要冲突通过。
- 实际HTTP串联：房间创建201、meta读取200（无nodes字段）；MCP新增返回direct及UID；相同ID重放返回duplicate；第二实例的真实Socket客户端收到一次UID匹配的事件。
- HTTP串联发现普通PATCH因空parentUid/index字段降级旧路径，已修正准入并通过针对性回归（空结构字段允许、实际重排仍走旧路径）。更新修正后、删除、自定义UID和根/SOP守卫未完成实际HTTP复测；第二轮启动遇到测试库既有schema初始化竞态，按快速交付要求停止扩展排查。不能把meta无nodes响应当作完整SQL性能采样证据。
- 前端一次独立目录构建通过，产物在 `.mcp-release/web/`；存在既有包体积警告。CodeGraph 已同步，状态为 up to date。

1000次优化前单节点写入样本已保留，P95 为510.55ms。按照用户“快速完成修复，不要过度校验”的要求，本轮没有再次运行10轮压测、13浏览器布局验收或完整故障矩阵。因此不声称 P95 减半、展开/收起改善或生产 LCP 改善；这些仍属于人工复测和后续性能验收。

## 发布与回滚

1. 先部署能够读取两种逆操作格式、连续补偿和权威快照的本版服务与客户端。
2. 没有新增数据库字段。归档幂等查询增加非唯一索引，人工使用 `psql -v ON_ERROR_STOP=1 -f simple-mind-map/migrations/009_mcp_archive_operation_id_index.up.sql`。此脚本使用 `CONCURRENTLY`，不得放入显式事务；失败后检查索引有效性再处理。生产尚未执行。
3. 默认 `COLLAB_V2_EVENT_BRIDGE=0`、`COLLAB_MCP_DIRECT=0`。先在测试房间开启事件桥，核对 `/api/health` 的监听健康、落后房间、补偿、重复通知及队列指标；再开启 MCP Direct。Direct 要求 V2 与事件桥同时启用，错误组合启动失败。
4. 人工复测实际 MCP 与浏览器并发、恢复和 UI 后，再确认生产放量。两个临时开关应记录配置与发布版本，避免各实例配置不一致。
5. 性能回滚关闭 `COLLAB_MCP_DIRECT`，保留事件桥和历史兼容能力。不要回退到不能读取新逆操作格式的旧版本。索引下线可人工执行对应 `.down.sql`，但在需要归档幂等查询时应保留索引。

通知中断时活跃房间版本核对会补偿；无法补齐日志时改走权威快照。队列满或超时返回可重试的繁忙错误，应使用相同 operation_id 重试。幂等仅保证仍保留的操作记录，不保证历史记录清理后的同 ID 永久唯一。
