# 节点正文 @人员

在节点文字编辑器（普通文本、Quill 富文本）中输入 `@`，弹出人员候选。继续输入姓名或账号可搜索；支持上下方向键选择、Enter/Tab 插入、Escape 关闭候选。中文输入法组合期间不处理选择快捷键。

富文本编辑器中选中的 `@姓名` 使用系统绿色和加粗，不带背景色，通过 Quill 内置格式随正文保存；姓名后面的空格与继续输入的正文恢复选择前的格式。之前已保存提及的浅绿背景也不再显示。

候选来源：`/api/wecom/contacts` 的企业通讯录，以及当前房间成员。通讯录每页 50 人，使用服务返回的 `nextCursor` 加载后续页；不再使用评论候选原先的前 8 人限制。节点正文允许选择自己，消息中心沿用原有规则，不向作者自己生成未读提醒。原评论入口也支持通讯录搜索、加载更多和错误重试。

人员选择仅在本次编辑会话中暂存。保存时，正文与仍出现在正文中的 `data.textMentions` 使用同一受保护的协作操作提交；取消/丢弃编辑、只读模式、切换房间时不写入。普通文字复制粘贴不复制结构化提及，避免仅粘贴姓名就重复提醒他人。

提及索引复用消息中心的 `comment_mentions`，但不向节点评论列表插入任何评论。每次选择有稳定 ID，正文修改不会重复生成提醒；索引从已提交快照建立，移除正文中的提及后不再显示。消息 DTO 的 `source=node_text`，点击直接定位节点，不打开评论框。

查看提醒仍遵循原有导图访问权限；选择人员不会自动授予房间权限。通讯录也受当前企业和企业微信应用的可见范围约束。企业微信不可用时，现有通讯录接口回退到已同步镜像；若镜像只有一个账号，前端无法凭空生成未同步的同事。

验证：

```powershell
node web/tests/nodeTextMention.test.cjs
node --test simple-mind-map/test/nodeTextMentions.test.cjs
```

另需在实际编辑器验证光标定位、富文本插入、中文输入法、选择后保存及原评论入口。
