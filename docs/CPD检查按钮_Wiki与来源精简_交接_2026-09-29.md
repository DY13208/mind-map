## 7. Wiki 契约与关键陷阱

API.md 文档基址是 `http://127.0.0.1:8989/wiki-compiler/`；本机 8989 实测拒绝连接。容器内部用 `http://wiki-graph:3848/api/...`，应用网关走 `/wiki-compiler/api/...`。容器 localhost 不是宿主机，不能直接照抄文档的回环地址。

服务无鉴权，不使用向量库或模型。

### 查询

```http
POST /api/search
Content-Type: application/json

{"query":"具体业务与缺项","top_k":30}
```

结果：`{query,results:[{chunk_id,score,topic,section,content,concepts,source,version}]}`。无结果为 200 + results[]。score 只是排序分值，不能自动确认流程。

- 当前有效 topics = INDEX 与 `.compile-state.json` 的交集。
- `chunk_id = topic::section::startLine`；content 是该小节正文，**不是完整 SOP**。
- source 是 Sources 原文行，没有就空数组，不能编造页码条款。
- version 可能只有编译日期，要同时比较正文 hash。

### 读取

`GET /api/topic/{编码主题名}` 返回 `{slug,title,meta,sections:[{heading,content}]}`。

**导航 API 能读残留旧文件。** 不得只因 GET 成功就当当前有效；要通过当前 search 命中复核，并核验小节原文 hash，再读取完整主题。

重要差异：search 的 section 去掉尾部 `[coverage:...]`，topic 返回的 heading 保留标记；匹配时需归一化，完整报告正文保留原始 heading。

完整主题任意 section 缺内容/非法类型、读取超限、超时、非法 JSON、无权限、来源不可用，均不能 complete/pass。不要把预算截断预览当全文。

同 topic 多小节命中应合并文档候选，降低重复全文读取；不同 topic/流程仍由用户选择。

```powershell
$taskInspection = (docker inspect mind-map-app-1 | ConvertFrom-Json)[0]
$taskPreservedEnvironment = @{}
foreach ($taskEntry in $taskInspection.Config.Env) {
  $taskParts = $taskEntry -split '=', 2
  $taskPreservedEnvironment[$taskParts[0]] = $taskParts[1].Replace('$', '$$')
  if ($taskParts[0] -match '^(KNOWLEDGE_MCP_|DOCMOST_|AUTH_)') {
    [Environment]::SetEnvironmentVariable($taskParts[0], $taskParts[1], 'Process')
  }
}
# 若用户提供了真实 Wiki 地址，在此明确加入相应值；否则用内部既有服务。
$taskPreservedEnvironment['CPD_WIKI_API_URL'] = 'http://wiki-graph:3848'
$taskComposeOverride = @{ services = @{ app = @{ environment = $taskPreservedEnvironment } } } | ConvertTo-Json -Depth 10 -Compress
$taskComposeOverride | docker compose -f docker-compose.yml -f docker-compose.wiki.yml -f - up -d --no-deps --force-recreate app
```

启动约需 10 秒；确认 app healthy、HTTP 200、运行容器内检查源码 hash 与宿主一致、新前端 bundle 生效。当前部署的旧 bundle 是 `/js/chunk-3c6346ea.js`，本轮不应继续用它判断新代码已生效。
