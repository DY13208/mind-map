# MCP 写入与多人协作：阶段性交付

## 交付范围（2026-10-16）

本轮在此前已推送的 `7efea140` 基础上补充修复。提交前工作树基于 `9bbfc752`（包含后续主分支合并）。只做本地构建和隔离验证；业务容器、业务数据库及线上均未部署或迁移。

本轮新增内容：

- 将 MCP UID 分类实际接入 Direct 入口。证明查询包含墓碑；明确 UID 移动及缺失 UUID 留给业务守卫处理，证明查询失败明确返回 `MCP_DIRECT_REFERENCE_UNAVAILABLE`，不静默退回全树写入。普通 HTTP 保持现有语义。
- 修复未来 ACK 与远端操作竞争：按实际完成的连续版本推进水位，缺口补齐后重放 canonical 字段，失败保留已成功前缀；房间、adapter、epoch 隔离，待完成记录有界。
- 增加受控 MCP HTTP 生命周期诊断，关联请求、操作与响应阶段；保持诊断权限、采样上限及脱敏，不记录正文、令牌或原始会话 ID。
- 修正回归测试夹具；补充 Direct 入口、ACK 连续完成与 HTTP 诊断测试。
- 保留隔离性能复现入口及其依赖，修正绝对槽调度、单调时钟计时、浏览器原子读回和受控文本比较。该入口仍在完善，不能视为验收已通过。

批量部分成功、依赖、幂等回执、移动、固定重试版本和附件兼容等此前修复见 [写入契约](./mcp-collab-write-contract.md)，本轮没有重新实现这些能力。

## 验证结果与限制

- 基于 `66228924` 加本轮产品补丁的隔离 HTTP/MCP 合约 30/30 通过，历史快照回归 26/26 通过；相关入口、ACK、诊断与驱动聚焦测试通过。
- 最新 `9bbfc752` 合并状态加本轮补丁的前端隔离构建通过（退出码 0）；产品四项聚焦脚本、五个产品文件语法检查通过。两个 Node 测试文件共 38 项通过、4 项 TODO、0 失败；TODO 未当作通过。产品修复独立提交为 `7bf1c0e9`。
- 新增验收工具的 12 个安全自测入口均取得通过结果。worker selftest 首次把 HTTP 回调到达间隔当作派发节拍，修正为落盘的单调派发时间并按实际计划槽差处理 missed 后，定向自测通过；收到请求、鉴权、错误分类及 missed 断言保留。初始失败与修正后结果均留在本地日志，不将重跑解释为产品性能达标。
- 隔离镜像 `candidate-v3` 的 30 秒自然视口十客户端预检为 **失败**。150 个 MCP 计划槽实发 141 次，全部成功且 Direct、无 full/legacy；9 次因驱动迟到未发送。
- 10,000 节点最终权威树与操作重放 hash 一致，十客户端收敛到 revision 273。该一致性不证明每次输入都形成了提交。
- MCP 返回 P95 22.66 秒，服务端 HTTP 区间 P95 22.35 秒；同房间 MCP 队列最高 90、active 为 1。节点 PATCH P95 约 1.27 秒，排队是外层等待的重要来源。
- 20 次浏览器编辑为 `missing_submit_trace` / `unfinished_deadline`，没有对应协作提交帧、operationId 或服务端拒绝码，尚不能解释为服务端 ACK 超时。首键反馈 P95 59.2ms，但按时编辑覆盖率仅 36.67%。
- 正常普通事件没有全树快照或 HTTP 恢复调用。旧轮 14 次连接中断在本轮未重现，仍缺达标负载下的关闭证据。

以上性能数据对应冻结镜像及当时源码，不自动覆盖之后合入的主分支代码。当前提交前构建/聚焦回归与历史隔离性能结果分开报告；完整性能验收、千节点全部绘制、三轮对照及十分钟持续负载均未完成。

## 第一阶段剩余事项

1. 保存已有 `mcp-queue` / `mcp-write` 逐操作阶段事件；当前入口只落盘 HTTP 生命周期和队列瞬时快照，不能精确拆分每项排队时长。
2. 查明浏览器输入至协作提交之间的 20 次缺口；保留失败项，不能只看最终树一致。
3. 定位同房间写锁、COMMIT 与串行队列的吞吐瓶颈，保持原有操作顺序和持久性保证。
4. 稳定实际负载节拍，补足 PG/Redis 容器 CPU、内存和容量观察；两次资源样本不足以证明容量余量。
5. 形成有效、可比较的 A/B/C 基线，再进入正式性能验收。

复现步骤与证据位置见 [阶段一验证入口](./mcp-stage1-baseline.md)。本轮删除重复的过程性文档内容，原始日志、镜像清单及清理前文档留在本机 `output/`，不纳入代码提交。
