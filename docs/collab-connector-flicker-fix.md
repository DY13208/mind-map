# 协同编辑连线闪烁修复

基于主分支 `787ac540`，2026-09-30 验证。

## 原因与修复边界

`Base.createNode()` 在布局计算中复用节点时调用 `MindMapNode.reset()`。
`reset()` 之前会删除该节点的全部连线；布局计算及性能绘制分多个异步任务执行，
因此每次增删、尺寸调整都会出现全图连线先清空再重建的中间帧。

普通复用现在保留已提交的连接线，随后 `renderLine()` 原位更新路径和裁剪多余槽位。
以下清理仍然保留：

- 移动/脱离父节点时清理受影响的旧父节点连线。
- 折叠、删除或退休的节点清理自身失效连线。
- 布局切换清理两个节点缓存及共享连线层。
- 延迟回调不能让已替换的节点实例重新创建连线。

未修改协同协议、历史数据格式、数据库或 ENV；不需要数据迁移。

本次只验证尺寸修改的本端绘制，没有改动现有尺寸协同同步逻辑。
真正的布局切换仍需重建连线；移动只清理受影响分支，不承诺这些操作零路径替换。
本地未启动 Wiki 图谱服务，使用诊断专用 Compose hosts 映射避免可选代理阻止 Nginx 启动；
